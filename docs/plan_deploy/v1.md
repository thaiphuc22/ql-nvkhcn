# Deploy bản demo full-stack qua Runlocal

## 1. Mục tiêu

Cho phép người được chia sẻ URL và mật khẩu truy cập tạm thời vào hai phiên bản:

- Bản React mock hiện có trên GitHub Pages.
- Bản full-stack chạy trên máy dev: Angular + Spring Boot + PostgreSQL + Camunda 8 Self-Managed.

Bản full-stack là môi trường demo ngắn hạn, best-effort, không phải production/UAT và không cam kết uptime. Máy dev phải bật, không sleep và giữ các tiến trình cần thiết trong suốt phiên demo.

Thuật ngữ “public” trong plan này chỉ có nghĩa là URL có thể truy cập từ Internet. Nội dung vẫn bị giới hạn bằng shared credential; không phải “ai có link cũng vào được”.

## 2. Hiện trạng và ràng buộc

- `webapp/` là React mock, đang deploy lên GitHub Pages bằng `.github/workflows/deploy-pages.yml`.
- `frontend-angular/` gọi Spring Boot ở cổng `8090`.
- Spring Boot gọi PostgreSQL ở `5432`, Camunda REST ở `8080`, Zeebe gRPC ở `26500` và BPMN test engine ở các cổng local riêng nếu được bật.
- Backend chưa có user/session/RBAC server-side. `DevApiKeyFilter` chỉ kiểm tra một static header `X-QTKHCN-Dev-Key`.
- Giá trị dev key hiện tại `dev-local-only` đã có trong source frontend nên không được coi là bí mật.
- GitHub Pages chỉ host static asset, không chạy được backend/database/Camunda.
- Không thuê VPS và không mở port trên router; dùng Runlocal outbound qua WebSocket/TLS 443.

Runlocal miễn phí chỉ phù hợp cho testing/development, không có SLA và URL thay đổi khi tiến trình tunnel chạy lại. Trên mạng doanh nghiệp, client phải đi qua HTTP proxy do PAC của Windows chỉ định và phải bypass proxy cho `127.0.0.1`. Nếu cần URL cố định hoặc demo dài ngày, chuyển sang gói có stable subdomain hoặc một môi trường hosting thực.

## 3. Các điều kiện bắt buộc trước khi mở tunnel

### 3.1. Gate về version control và khả năng tái lập

Hiện `backend/`, `frontend-angular/` và phần lớn `infra/` đang untracked. Không được coi bản deploy là tái lập được cho đến khi hoàn thành các việc sau:

1. Bổ sung `.gitignore` cho tối thiểu:
   - `node_modules/`, `dist/`, `.angular/`.
   - `backend/target/`.
   - `*.log`, `*.out.log`, `*.err.log`.
   - `.env*`, ngoại trừ file `.env.example` nếu cần.
   - File chứa password, password hash, API key, connector secret và database dump.
2. Review rồi commit source/config cần thiết của `backend/`, `frontend-angular/` và hạ tầng do dự án sở hữu.
3. Không commit build output, log, database volume, password/hash/API key thật hoặc các file secret của Camunda connector.
4. Xác nhận một checkout sạch có thể build Angular và backend theo README.

Nếu chưa thể commit baseline full-stack, vẫn có thể chạy demo local để thử nghiệm, nhưng phải ghi rõ đây là runbook phụ thuộc duy nhất vào máy hiện tại. Không publish link cho stakeholder như một môi trường có khả năng phục hồi.

### 3.2. Gate về dữ liệu

- Chỉ dùng dữ liệu demo/đã ẩn danh; không dùng dữ liệu cá nhân, mật hoặc dữ liệu nghiệp vụ thật chưa được phép chia sẻ qua nhà cung cấp tunnel.
- Tạo backup/snapshot PostgreSQL trước phiên demo.
- Có cách reset lại dữ liệu sau phiên demo.
- Xác nhận người nhận credential có được phép thực hiện các thao tác ghi như import/deploy BPMN, tạo hồ sơ và xử lý action hay không.

Basic Auth chỉ xác nhận người biết shared credential; nó không tạo RBAC. Mọi người dùng credential đều có cùng quyền trên toàn bộ API.

### 3.3. Gate về network binding

Không chỉ dựa vào Windows Firewall. Các dịch vụ nội bộ phải bind loopback để không thể bỏ qua Caddy từ LAN:

- Caddy: `127.0.0.1:8443`.
- Spring Boot: `127.0.0.1:8090`.
- PostgreSQL: `127.0.0.1:5432`.
- Camunda REST/management/Zeebe: `127.0.0.1:8080`, `127.0.0.1:9600`, `127.0.0.1:26500`.
- Connector/test-engine và các cổng phụ khác cũng bind `127.0.0.1` nếu được publish từ Docker.

Các mapping Docker dạng `"8080:8080"` hoặc `"5432:5432"` hiện bind mọi interface và phải đổi thành dạng `"127.0.0.1:8080:8080"`, `"127.0.0.1:5432:5432"`, v.v. Việc hardening này nằm trong scope của plan.

## 4. Kiến trúc mục tiêu

```text
GitHub Pages
└── React mock
    └── banner/link chỉ chứa URL Runlocal, không chứa credential

Internet
└── HTTPS: https://<random>.runlocal.eu
    └── Runlocal (outbound WebSocket/TLS 443, qua HTTP proxy nếu bắt buộc)
        └── HTTP: 127.0.0.1:8443
            └── Caddy
                ├── Basic Auth bảo vệ toàn site
                ├── /api/* → 127.0.0.1:8090, giữ nguyên prefix /api
                │             và inject X-QTKHCN-Dev-Key ở proxy
                └── /*       → Angular static dist + SPA fallback

Chỉ loopback, không tunnel trực tiếp
├── Spring Boot 127.0.0.1:8090
├── PostgreSQL 127.0.0.1:5432
├── Camunda REST 127.0.0.1:8080
├── Camunda management 127.0.0.1:9600
└── Zeebe gRPC 127.0.0.1:26500
```

UI và API có cùng public origin nên browser không cần CORS. `WebConfig.java` có thể giữ cấu hình CORS dành cho `ng serve` local.

## 5. Thiết kế routing API chuẩn

Giữ contract public và backend là `/api/...` xuyên suốt, không tạo `/api/api/...` và không strip `/api` tại proxy.

### Angular

- Dev local: `API_BASE_URL = 'http://localhost:8090'`.
- Demo qua Caddy: `API_BASE_URL = ''`.
- Các service hiện ghép `${API_BASE_URL}/api/...`, do đó:
  - Dev local gọi `http://localhost:8090/api/...`.
  - Demo gọi `/api/...` cùng origin.

### Caddy

Dùng `handle /api/*`, không dùng `handle_path`, vì `handle_path` tự strip prefix đã match.

Request `/api/ho-so` phải tới backend nguyên vẹn dưới dạng `/api/ho-so`.

## 6. Việc sẽ triển khai

### 6.1. Angular: tách environment và không phát dev API key trong demo bundle

Tạo:

- `frontend-angular/src/environments/environment.ts`
- `frontend-angular/src/environments/environment.demo.ts`

Contract đề xuất:

```ts
// environment.ts
export const environment = {
  apiBaseUrl: 'http://localhost:8090',
  devApiKeyValue: 'dev-local-only',
};
```

```ts
// environment.demo.ts
export const environment = {
  apiBaseUrl: '',
  devApiKeyValue: '',
};
```

Sửa `frontend-angular/src/app/core/api-config.ts` để giữ nguyên các export hiện có nhưng đọc từ `environment`:

- `API_BASE_URL` lấy từ `environment.apiBaseUrl`.
- `DEV_API_KEY_VALUE` lấy từ `environment.devApiKeyValue`.
- `DEV_API_KEY_HEADER` và `encodeAuditActor()` giữ nguyên.

Sửa `dev-api-key.interceptor.ts`:

- Chỉ attach header khi `DEV_API_KEY_VALUE` khác rỗng.
- Chỉ attach cho URL backend phù hợp; không để `API_BASE_URL === ''` khiến interceptor match mọi HTTP request.
- Demo build không gửi `X-QTKHCN-Dev-Key` từ browser; Caddy sẽ inject header server-side.

Thêm `build.configurations.demo.fileReplacements` trong `angular.json` để thay `environment.ts` bằng `environment.demo.ts`.

Build demo bằng:

```powershell
cd frontend-angular
npx ng build --configuration=production,demo
```

### 6.2. Backend: bind loopback và rotate dev API key theo từng phiên

Không tạo Spring profile auth mới trong scope này. Khi chạy phiên demo:

- Sinh một API key ngẫu nhiên, khác `dev-local-only`.
- Truyền cùng key cho backend và Caddy qua environment variable/local process environment.
- Bind Spring Boot vào `127.0.0.1`.

Ví dụ biến môi trường PowerShell:

```powershell
$env:QTKHCN_DEV_API_KEY = '<random-per-session-key>'
$env:SERVER_ADDRESS = '127.0.0.1'
```

Không ghi key thật vào README, Caddyfile, Git history hoặc GitHub Pages JSON.

### 6.3. Docker: giới hạn toàn bộ published port vào loopback

Cập nhật cấu hình Compose local dùng cho demo để mọi `ports` có `127.0.0.1:` ở phía host. Bao gồm tối thiểu PostgreSQL, Camunda REST, management, Zeebe, Connectors và BPMN test engine nếu chạy.

Sau khi `docker compose up -d`, dùng `Get-NetTCPConnection` hoặc `netstat` để xác nhận không có cổng nội bộ nào listen trên `0.0.0.0` hoặc `::`.

### 6.4. Reverse proxy: `infra/demo-tunnel/`

Tạo:

- `infra/demo-tunnel/Caddyfile`
- `infra/demo-tunnel/README.md`
- Có thể thêm script preflight/start/stop PowerShell nếu giúp giảm thao tác thủ công.

Caddyfile mục tiêu:

```caddyfile
http://127.0.0.1:8443 {
    basic_auth {
        demo {$DEMO_BASIC_AUTH_HASH}
    }

    handle /api/* {
        reverse_proxy 127.0.0.1:8090 {
            header_up X-QTKHCN-Dev-Key {$QTKHCN_DEV_API_KEY}
        }
    }

    handle {
        root * ./frontend-angular/dist/frontend-angular/browser
        try_files {path} /index.html
        file_server
    }
}
```

Không paste password hash thật vào Caddyfile được commit. Tạo hash và giữ trong environment variable của terminal chạy Caddy:

```powershell
$env:DEMO_BASIC_AUTH_HASH = caddy hash-password
```

Khi gán hash thủ công trong PowerShell phải dùng cách không làm `$` trong bcrypt bị nội suy.

README phải yêu cầu chạy `caddy validate` trước `caddy run`, và chạy lệnh từ repository root để relative static root trỏ đúng thư mục `dist`.

### 6.5. Runlocal tunnel

Cài Caddy nếu chưa có; Runlocal dùng Node.js/npm hiện có:

```powershell
winget install --id CaddyServer.Caddy --exact
```

Sau khi Caddy local đã qua smoke test:

```powershell
& .\infra\demo-tunnel\Start-DemoTunnel.ps1

# Khi mạng doanh nghiệp bắt buộc dùng proxy theo PAC:
& .\infra\demo-tunnel\Start-DemoTunnel.ps1 -ProxyUrl 'http://<proxy-host>:<proxy-port>'
```

Lưu ý trong README:

- URL `runlocal.eu` thay đổi mỗi lần tạo tunnel miễn phí.
- Runlocal miễn phí không có SLA và chỉ dùng cho demo/testing.
- Không commit proxy URL nội bộ hoặc Runlocal inspector URL.
- Đặt `GLOBAL_AGENT_NO_PROXY=127.0.0.1,localhost` khi đi qua proxy doanh nghiệp.
- Không share URL trước khi xác nhận Basic Auth hoạt động từ một mạng ngoài.

### 6.6. React mock: banner liên kết sang demo full-stack

Thêm `webapp/public/be-demo-link.json`:

```json
{
  "url": "",
  "note": ""
}
```

Sửa `webapp/src/App.tsx` để:

- Fetch `${import.meta.env.BASE_URL}be-demo-link.json`.
- Có xử lý HTTP error, JSON không hợp lệ và component unmount.
- Chỉ chấp nhận URL dùng `https:`; fail closed nếu URL không hợp lệ.
- Có chiến lược tránh giữ link cũ do cache, ví dụ `cache: 'no-store'` hoặc cache-busting phù hợp.
- Không hiển thị gì khi URL rỗng hoặc fetch lỗi.
- Mở tab mới với `rel="noopener noreferrer"`.
- Không đưa username, password, password hash hoặc API key vào JSON/note.

Việc thay JSON và push vẫn kích hoạt workflow GitHub Pages hiện tại, bao gồm `npm ci` và `npm run build`. Lợi ích của JSON runtime là không phải sửa/rebundle source cho mỗi URL, không phải là CI hoàn toàn bỏ qua bước build.

## 7. Runbook mở phiên demo

1. Xác nhận working tree và source baseline phù hợp; không vô tình publish secret/log/build output.
2. Tạo backup/snapshot dữ liệu demo.
3. Bind các port Docker vào `127.0.0.1`, khởi động PostgreSQL và Camunda.
4. Sinh `QTKHCN_DEV_API_KEY` ngẫu nhiên cho phiên hiện tại.
5. Khởi động backend với key đó và `SERVER_ADDRESS=127.0.0.1`.
6. Build Angular bằng configuration `production,demo`.
7. Sinh Basic Auth hash vào environment variable, không ghi vào file tracked.
8. Chạy `caddy validate`, sau đó `caddy run` từ repository root.
9. Smoke test trực tiếp `http://127.0.0.1:8443`.
10. Chạy Runlocal tunnel tới `http://127.0.0.1:8443`, qua HTTP proxy nếu PAC của mạng yêu cầu.
11. Từ mạng ngoài, xác nhận sai/thiếu Basic Auth bị từ chối trước khi chia sẻ URL.
12. Cập nhật `webapp/public/be-demo-link.json` chỉ với HTTPS URL của tunnel rồi deploy GitHub Pages.
13. Gửi username/password riêng qua kênh được phép; không đăng credential trên GitHub Pages hoặc repository.
14. Theo dõi log Caddy, Runlocal và backend trong suốt phiên demo; không chia sẻ inspector URL và log không được chứa credential/header bí mật.

## 8. Verification bắt buộc

### 8.1. Build và static inspection

- `npx ng build --configuration=production,demo` thành công.
- Chạy unit tests Angular hiện có.
- Dist demo không chứa `localhost:8090`.
- Dist demo không chứa API key ngẫu nhiên của phiên.
- Xác nhận request do frontend tạo là `/api/...`, không phải `/api/api/...`.
- `npm run build` trong `webapp/` thành công.

### 8.2. Network isolation

- `127.0.0.1:8443` listen loopback.
- `8090`, `5432`, `8080`, `9600`, `26500` và các cổng phụ chỉ listen loopback.
- Không có listener tương ứng trên `0.0.0.0` hoặc `::`.
- Từ máy khác trong LAN, truy cập trực tiếp `http://<dev-ip>:8090`, PostgreSQL và Camunda thất bại.

### 8.3. Auth và routing

- Không có Basic Auth → `401`.
- Sai Basic Auth → `401`.
- Đúng Basic Auth → Angular `index.html` và asset tải thành công.
- Refresh trực tiếp một Angular route → SPA fallback hoạt động.
- `/api/ho-so` đi qua Caddy và backend trả dữ liệu thật.
- Backend từ chối request trực tiếp nếu thiếu/sai API key.
- Browser không gặp lỗi CORS vì UI/API cùng origin.

### 8.4. Kiểm thử từ Internet

Từ 4G hoặc một mạng ngoài:

1. Mở URL Runlocal.
2. Xác nhận Basic Auth xuất hiện trước UI.
3. Đăng nhập bằng shared credential.
4. Mở Angular UI và thực hiện một kịch bản đọc dữ liệu.
5. Nếu stakeholder được phép ghi, thực hiện một kịch bản ghi có thể reset.
6. Xác nhận Camunda/PostgreSQL/backend không có public URL riêng.

### 8.5. React banner

- URL rỗng → không hiển thị link.
- URL HTTPS hợp lệ → hiển thị và mở đúng tab mới.
- JSON lỗi, HTTP lỗi hoặc URL không phải HTTPS → fail closed, không hiển thị link.
- Sau khi tắt demo và deploy JSON rỗng, link cũ biến mất.

## 9. Runbook đóng phiên và rollback

1. Đưa `be-demo-link.json` về trạng thái URL rỗng và deploy GitHub Pages.
2. Dừng tiến trình Runlocal trước để cắt public access.
3. Dừng Caddy.
4. Dừng backend; dừng Docker stack nếu không còn dùng.
5. Xác nhận các port `8443`, `8090`, `5432`, `8080`, `9600`, `26500` không còn public/listen ngoài dự kiến.
6. Xóa các environment variable chứa Basic Auth hash và API key khỏi terminal/session.
7. Rotate shared password/key trước phiên demo tiếp theo.
8. Reset hoặc restore dữ liệu demo nếu người xem đã thực hiện thao tác ghi.
9. Kiểm tra Git status để chắc chắn không có secret/log/dump bị đưa vào working tree chuẩn bị commit.

Rollback khi phát hiện sự cố trong lúc demo: dừng tiến trình Runlocal ngay lập tức. Đây là kill switch ưu tiên; sau đó mới điều tra Caddy/backend/data.

## 10. Ngoài phạm vi

- Xây dựng OIDC/SAML/JWT/session/RBAC hoàn chỉnh ở backend.
- Sử dụng Basic Auth như giải pháp production.
- Stable/custom tunnel domain, access gateway/WAF hoặc SLA.
- Hosting backend/database/Camunda 24/7.
- Expose trực tiếp Camunda Operate/Tasklist, Zeebe, PostgreSQL hoặc Spring Boot ra Internet.
- Dùng dữ liệu nghiệp vụ thật chưa được phê duyệt.

## 11. Tiêu chí Go/No-Go

Chỉ được chia sẻ URL khi tất cả điều kiện sau đạt:

- Routing là `/api/...` xuyên suốt và smoke test xanh.
- Basic Auth chặn toàn bộ UI/API.
- API key phiên được inject server-side, không nằm trong demo bundle.
- Tất cả dịch vụ nội bộ chỉ bind loopback.
- Dữ liệu đã được xác nhận an toàn để demo và đã có backup/reset.
- Không có credential trong Git, GitHub Pages JSON hoặc log.
- Đã kiểm thử từ một mạng ngoài.

Chỉ cần một điều kiện trên không đạt thì quyết định là **No-Go**; không mở tunnel cho stakeholder.
